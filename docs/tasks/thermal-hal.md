# Confirm the stock thermal HAL replaces the source build

The swap is in the tree — three blobs added to `proprietary-files.txt`, the
`android.hardware.thermal-service.qti` package dropped from `device.mk`. See
[thermal.md](../reference/thermal.md) for why.

Blobs are not regenerated by a device tree change, so this needs
`extract-frogger.sh` on the server before the next build, or the HAL is simply
absent and `check_vintf` fails on a mandatory missing interface.

## Verify on the flashed build

```sh
adb shell ls -l /vendor/bin/hw/android.hardware.thermal-service.qti
```

239008 bytes is stock's, 301744 the source build's.

```sh
adb logcat -d | grep -i "Thresholds is not defined"
adb shell dumpsys thermalservice | grep -A2 "HAL connection"
```

The threshold message confirms the blob found no configuration and will report
no severity. `Thermal Status: 0` should then hold with the device warm — worth
checking under a load that used to trip it, not at idle, since the source HAL
only misbehaved above 36.5 °C skin.
